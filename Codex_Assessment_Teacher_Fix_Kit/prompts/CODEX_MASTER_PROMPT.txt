Mục tiêu chính:
1. Sửa trang Teacher > Grading đang chỉ có sidebar và vùng nội dung trống.
2. Sửa trang Teacher > Assignments đang mất layout/CSS và có dữ liệu mẫu hoặc hard-code.
3. Hoàn thiện end-to-end các chức năng Assessment ASM-01 đến ASM-06, ưu tiên Teacher-side ASM-04, ASM-05, ASM-06 và bảo đảm Student-side ASM-01, ASM-02, ASM-03 tích hợp đúng.
4. Không chỉ sửa giao diện; phải sửa controller, service, repository, security, model/DTO, template, CSS/JS và migration khi thực sự cần.

Cách làm bắt buộc:

GIAI ĐOẠN A — KHẢO SÁT, CHƯA SỬA CODE
- Đọc cấu trúc repository và convention hiện tại.
- Tìm toàn bộ route/controller/service/repository/entity/template/CSS/JS/test liên quan assessment.
- Truy vết link Grading và Assignments từ sidebar đến route và view.
- Xác minh root cause bằng source code, log, test hoặc HTTP response.
- Kiểm tra layout fragment, static asset path, Spring Security, model attribute và hard-coded data.
- Lập kế hoạch file-level ngắn gọn.
- Không tạo implementation song song khi dự án đã có service/entity tương ứng.

GIAI ĐOẠN B — SỬA RENDER VÀ DATA PIPELINE
- Làm Grading và Assignments render đúng Instructor Portal.
- Dùng layout/design system hiện có.
- CSS/JS phải tải đúng bằng đường dẫn phù hợp.
- Xóa row hard-code khỏi production.
- Lấy dữ liệu từ database theo authenticated Teacher.
- Có empty state khi chưa có dữ liệu.
- Backend kiểm tra ownership; không chỉ ẩn UI.

GIAI ĐOẠN C — HOÀN THIỆN NGHIỆP VỤ
- ASM-04: Teacher quản lý quiz/question/answer.
- ASM-05: Teacher quản lý testcase và hệ thống chấm code qua adapter an toàn.
- ASM-06: Teacher xem queue, chấm điểm, feedback, lưu/publish.
- Xác minh ASM-01/02/03 vẫn hoạt động và kết nối đúng.
- Không chạy code Student bằng Runtime.exec/ProcessBuilder trong web process.
- Nếu chưa có code runner production, tạo adapter interface + HTTP implementation cấu hình bằng property/env và fake adapter cho test. UI phải báo đúng trạng thái khi service chưa cấu hình; không giả điểm.

GIAI ĐOẠN D — TEST
- Thêm/sửa unit test, repository test, MockMvc/integration test.
- Test role và ownership.
- Test static assets không bị chặn nếu phù hợp.
- Chạy ./mvnw test hoặc .\mvnw.cmd test.
- Không disable test để làm build xanh.
- Nếu lỗi môi trường, ghi rõ lệnh, stack/error chính và phân biệt với lỗi code.

GIAI ĐOẠN E — BÁO CÁO
Dùng docs/10_CODEX_OUTPUT_TEMPLATE.md để báo cáo:
- root causes;
- files changed;
- database changes;
- security;
- test results;
- manual verification;
- ASM-01..ASM-06;
- AC-01..AC-08;
- remaining limitations.

Ràng buộc:
- Không hard-code.
- Không xóa dữ liệu/database.
- Không đổi kiến trúc lớn khi không cần.
- Không làm hỏng Student/Teacher/Admin routes khác.
- Không commit secret.
- Không tuyên bố “completed” nếu chưa chứng minh bằng test hoặc kiểm tra.
- Nếu cần đưa ra giả định, ghi rõ giả định trước khi dùng.
